# Enrolment: the QR carries an envelope Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A phone gets everything it needs from one scan — where the box is, who it is, and which certificate to demand — so adding a phone never again means recompiling an app.

**Architecture:** The QR stops being a link to a welcome page and becomes a JSON envelope `{v, url, token, ca}`. That inverts an ordering that exists today: the per-person secret is currently minted when the welcome page is REQUESTED, and it must now exist before the QR is drawn — so the QR becomes per-person and is regenerated by `Enrolment.abrir()` instead of once at `serve()`. Separately, the socket already resolves who a token belongs to (`Guard.persona_for`) and simply never says so; the handshake gains one frame that does.

**Tech Stack:** Python 3.12, aiohttp, `qrcode[png]`, openssl through `subprocess` (as `certs.py` already does). No new dependency.

**Spec:** `/home/nexus/2026-09-06-enrolamiento-cambios-en-el-widget.md` — the contract, agreed with the iOS side 2026-09-06. Read it first; this plan argues from it.

## Global Constraints

- **Spanish for anything a person reads or hears; English for code, comments and commit messages** (CLAUDE.md §2.9, §6).
- **`ruff format` and `ruff check` must pass.** Type hints mandatory on public functions.
- **`PYTHONNOUSERSITE=1` on every invocation.** A venv with `--system-site-packages` also sees `~/.local/lib`.
- **Tests:** `cd widget && PYTHONNOUSERSITE=1 .venv/bin/python -m pytest -q`
- **No test touches the network, the GPU, a display or a microphone.** A test MAY shell out to `openssl` — `tests/test_certs.py` already does.
- **The app never sends a name or a `user_id`** (spec, "Lo que NO debe cambiar"). The token stays the only thing a phone can say about itself, and the box stays the one that maps token → person → `chat_id`. Nothing in this plan may add a client-supplied identity.
- **`nameConstraints` on the CA stays limited to `brain.local` and the LAN.** Not touched here.
- **The envelope's four fields are all mandatory**, and the app rejects an incomplete one rather than falling back. So the box must never write a partial envelope: no field may be defaulted or omitted.
- **`ca` is the hash of the CA's PUBLIC KEY (SPKI), not of the certificate.** Renewing the leaf while keeping the key must not invalidate enrolled phones.

## Decisions taken before this plan, so nobody re-opens them

- **The QR carries the envelope and nothing else** (owner, 2026-09-06). A phone without the app reaches the welcome page by typing the address. `static/movil.html` is not touched and not deleted — **the web interface is going to be deprecated**, so its loss of scannability is accepted rather than worked around.
- **`v` is `1`.** An unknown version is the app's problem to reject; the box only ever writes the version it knows.

```python
def spki_fingerprint(ca_pem: Path) -> str:
    """The CA's public key, SHA-256, in the HPKP form the phone pins.

    **The key, not the certificate**, and that is the whole design: a
    leaf reissued from the same key keeps every enrolled phone working,
    where pinning the certificate would strand all of them on the day it
    is renewed. The cost, and it belongs written down next to the code
    rather than only in the contract: ROTATING THE CA KEY means
    re-enrolling every phone in the house.

    Shells out to `openssl` rather than reaching for `cryptography`,
    because this module already does exactly that for every other
    certificate operation and adding a second way to do the same job is
    how two of them drift apart. Four processes, once per QR — the cost
    is invisible next to `openssl req`, which this module already runs.
    """
    pubkey = _capture(["openssl", "x509", "-in", str(ca_pem), "-pubkey", "-noout"])
    der = _capture(["openssl", "pkey", "-pubin", "-outform", "der"], stdin=pubkey)
    digest = hashlib.sha256(der).digest()
    return "sha256/" + base64.b64encode(digest).decode("ascii")


def _capture(args: list[str], stdin: bytes | None = None) -> bytes:
    """`_run`'s sibling for the two steps whose OUTPUT is the point.

    `_run` exists for commands that either work or must raise; these two
    are pipes. Same `check=True` posture: a failure here must not become
    an empty fingerprint, which would produce an envelope the app
    accepts and then cannot verify against anything.
    """
    return subprocess.run(
        args, input=stdin, capture_output=True, check=True
    ).stdout
```

```python
# The envelope's format version. The app rejects a version it does not
# know, so this number is a promise: change it only when a field
# changes meaning, never when one is added.
VERSION_SOBRE = 1


def sobre(*, url: str, token: str, ca: str) -> str:
    """Everything a phone needs, as the JSON that goes inside the QR.

    Four mandatory fields and no defaults, deliberately: the app
    rejects an incomplete envelope outright rather than falling back to
    the system's own certificate validation, which is the property that
    makes pinning worth anything. So a missing field has to fail HERE,
    where there is a traceback and a journal, and not on a phone whose
    only symptom is a scan that does nothing.

    `wss` is checked for the same reason. A QR offering `ws://` is a
    box that has been misconfigured into plaintext, and the app drops it
    before connecting — so it must never be written.
    """
    if not url or not token or not ca:
        raise ValueError("un sobre incompleto no se escribe: url, token y ca son obligatorios")
    if not url.startswith("wss://"):
        raise ValueError(f"el sobre exige wss, no {url!r}")
    return json.dumps(
        {"v": VERSION_SOBRE, "url": url, "token": token, "ca": ca},
        # Compact and stable: a QR's size is its scannability, and a
        # sorted, space-free payload is also diffable in a log.
        separators=(",", ":"),
    )
```

### Task 3: The QR becomes per-person, and is drawn when the window opens

**Files:**
- Modify: `widget/jarvis_widget/remote.py` (`Enrolment`, `serve`)
- Test: `widget/tests/test_remote.py`

**Interfaces:**
- Consumes: `enrol.sobre(...)` (Task 2), `certs.spki_fingerprint(...)` (Task 1), existing `enrol.write_qr(payload, path) -> Path`.
- Produces: `Enrolment.abrir(persona, now=None)` additionally writes `~/.jarvis/enrol-qr.png` containing that person's envelope. `Enrolment.attach_qr(escribir: Callable[[str], None]) -> None` is how `serve()` injects the writer, so the class stays free of paths, certificates and openssl.

**Why this shape.** `Enrolment` is a clock with a name in it, and it is unit-tested by driving that clock with no sockets and no filesystem. Handing it a `write_qr` call directly would drag openssl and a real CA into every one of those tests. It takes a callback instead, exactly as it already takes `EnrolmentSite` through `attach`.

**The ordering this fixes.** Today `serve()` draws one generic QR at startup and the person's secret is minted later, inside `_welcome`, on request. With the token inside the QR that is backwards: the secret must exist BEFORE the image is written. The minting therefore moves to `abrir()`. `_welcome` keeps its own minting — a phone with no app still reaches the page and must still work — and `Guard.secretos` is the single place both read, so the second caller finds the secret already there and mints nothing.

### Task 6: Prove it against the running box

**Files:** none — this task produces a measurement, not code.

Nothing above proves a phone can use any of it. These are the checks the contract itself proposes, run here without an iPhone.

- [ ] **Step 1: Open a window and read the QR back**

```bash
systemctl --user restart jarvis-widget.service
# open the window for a person, the way tools/enrolar.py does
cd widget && PYTHONNOUSERSITE=1 .venv/bin/python tools/enrolar.py Nata
```

Then decode the PNG and check the envelope has four fields, `v` is 1 and `url` starts `wss://`:

```bash
cd widget && PYTHONNOUSERSITE=1 .venv/bin/python -c "
import json, sys
from PIL import Image           # if unavailable, read the payload from the journal line instead
from pyzbar.pyzbar import decode
print(json.loads(decode(Image.open('$HOME/.jarvis/enrol-qr.png'))[0].data))
"
```

If `pyzbar`/`PIL` are not installed, do NOT add them as dependencies for a one-off check — print the payload from `_dibujar_qr` behind a temporary line instead, and remove it.

- [ ] **Step 2: Check the fingerprint against the certificate the box actually serves**

```bash
openssl s_client -connect "$(hostname -I | awk '{print $1}'):8443" -showcerts </dev/null 2>/dev/null \
  | openssl x509 -pubkey -noout | openssl pkey -pubin -outform der \
  | openssl dgst -sha256 -binary | openssl base64
```

This is the LEAF's key and will NOT match `ca` — that is correct and expected. The check that matters is that the leaf verifies against the CA whose SPKI the envelope pins:

```bash
openssl s_client -connect "$(hostname -I | awk '{print $1}'):8443" \
  -CAfile ~/.jarvis/certs/ca.pem </dev/null 2>&1 | grep -E "Verify return code"
```
Expected: `Verify return code: 0 (ok)`.

And the negative case, which is the one that proves pinning is worth anything — a DIFFERENT CA must fail:

```bash
openssl req -x509 -newkey rsa:2048 -nodes -keyout /tmp/otra.key -out /tmp/otra.pem -days 1 -subj "/CN=otra" 2>/dev/null
openssl s_client -connect "$(hostname -I | awk '{print $1}'):8443" \
  -CAfile /tmp/otra.pem </dev/null 2>&1 | grep -E "Verify return code"
```
Expected: a non-zero verify code.

- [ ] **Step 3: Check the handshake names the person**

```bash
cd widget && PYTHONNOUSERSITE=1 .venv/bin/python -c "
import asyncio, json, ssl, websockets
async def main():
    ctx = ssl.create_default_context(cafile='$HOME/.jarvis/certs/ca.pem')
    token = json.load(open('$HOME/.jarvis/personas.json'))['nata']
    async with websockets.connect(f'wss://brain.local:8443/ws?t={token}',
                                  ssl=ctx, origin='https://brain.local:8443') as ws:
        print(await asyncio.wait_for(ws.recv(), timeout=10))
asyncio.run(main())
"
```
Expected: `{"type": "enrolled", "name": "Nata"}`.

## What this plan does not do

- **It does not touch `static/movil.html`.** The web interface is going to be deprecated (owner, 2026-09-06); this plan neither fixes nor removes it, and it stops being reachable by scanning.
- **It does not add un-enrolling from the box.** A phone finds out when its token stops being accepted, and the contract says that is enough.
- **It does not change `nameConstraints`, the CA's lifetime, or anything about `jarvis_vision`.**
- **It cannot prove the iOS side.** The app is being written against this contract in another repo; Task 6 is the most this box can check alone.
